# Diagnostic tools for v0.3.0

Agents must be able to inspect retained logs, execution inputs and outputs, resource specifications, and pod failures without changing a workflow. This version adds five read-only tools, improves existing reads, and makes release identity verifiable. Existing mutation policy remains unchanged.

## Contract and ownership

`design/*.go` owns the MCP contract and all three transports advertise the same 30 tools. `internal/service` enforces policy and projects bounded results. `internal/argoapi` calls Argo; a separate `internal/kubeapi` client handles optional Kubernetes reads. Generated MCP files and projected upstream models remain generator outputs. Runtime configuration uses environment variables only.

All namespaced reads resolve the existing default namespace and authorize it before any upstream request. Namespaces, resource names, UIDs, node IDs, artifact names and container names must be nonempty safe path segments (no slash, backslash, control characters, dot segments or encoded traversal). Archive reads send the authorized namespace and verify returned namespace, UID and requested workflow name. A missing resource is an error, not an empty success. All five tools advertise read-only and non-destructive annotations and remain discoverable when a backend is unconfigured.

| Capability | Inputs and defaults | Result and routing |
| --- | --- | --- |
| `read_workflow_artifact` | namespace, required name/node_id/artifact_name, direction inputs/outputs default outputs, optional archive_uid, offset_bytes default 0 (0–16777216), max_bytes default 65536 (4–262144) | Read only an artifact declared on the selected node of the authorized workflow. Return UTF-8 text, bytes returned, next_offset, has_more, source and note. Build the Argo artifact route from trusted segments; never accept a URL. |
| `get_resource_spec` | kind workflow/workflow_template/cluster_workflow_template/cron_workflow, required name, namespace, section summary/arguments/templates/spec default summary, optional template_name, max_bytes default 65536 (1024–262144) | Return a JSON string preserving the selected upstream fields. Summary includes entrypoint, arguments, template names and workflowTemplateRef; cron summary selects workflowSpec. Arguments/templates select those spec fields; spec selects the complete spec. template_name is legal only with templates and must match exactly one template. Oversize results fail with narrowing guidance; JSON is never cut mid-document. |
| `get_workflow_pod_diagnostics` | namespace, required name, optional pod_name, limit default 20 (1–50), continue | Read current workflow UID from Argo; query Kubernetes pods by workflow label, additionally verify namespace and Workflow ownerReference UID. Return bounded pod summaries, node name, conditions, init/container current and previous state, restart counts and UID-scoped events. Return an opaque continuation for additional upstream pages. |
| `wait_workflow` | namespace, required name, duration_seconds default 10 (1–30), poll_interval_seconds default 2 (1–5) | Poll the existing workflow detail endpoint until Succeeded/Failed/Error, own deadline, or caller cancellation. Return latest detail, completed and timed_out; failed workflow completion is a successful read. |
| `get_server_context` | no inputs | Return build version, declared MCP version, transport, default namespace, configured allowed/denied namespaces, mutation/destructive/confirmation flags, Argo and Kubernetes configured flags and upstream Argo version/status. No credentials, raw configuration or endpoint URLs. Local namespace policy is explicitly not an RBAC enumeration. |

Cluster template spec reads match existing cluster template reads: no namespace policy or default applies, upstream cluster RBAC authorizes access, and an explicit namespace argument is rejected. Other spec reads use the existing respective GET routes. Resource responses must match requested name and namespace. Spec HTTP bodies are capped at 8 MiB before decoding. Absent optional sections return an empty object/array as appropriate; missing named templates return not-found. Parameter defaults, valueFrom, input declarations, DAGs, retries, synchronization and pod settings are available in unabridged spec sections without broadening the typed model projection unnecessarily.

## Artifact and log semantics

Artifact routes follow Argo's UI: `/artifact-files/{namespace}/{workflows|archived-workflows}/{name|uid}/{node}/{inputs|outputs}/{artifact}`. Without archive_uid, workflow data and artifacts use the live workflow route even when its pods have been deleted. With archive_uid they use the archive routes. No implicit archive search or name-to-UID guess is performed: a deleted workflow requires archive_uid discovered through list_archived_workflows; a live workflow lookup 404 returns this guidance. This also applies to log fallback.

The HTTP client must refuse cross-origin redirects and must not forward Argo credentials to a different origin. Same-origin means identical scheme and host/port (case-insensitive host); permit at most five redirect hops. Read at most offset + max_bytes + 4 bytes and always close the body. Reject non-success responses without echoing response bodies. Text means valid UTF-8 with no NUL; no additional heuristic rejects valid text. Send Accept-Encoding: identity, reject nonempty Content-Encoding other than identity, and do not unpack archives. Nonzero offsets that split UTF-8 characters fail. End chunks stop at a rune boundary; next_offset counts original bytes. has_more is determined by bounded lookahead. A result must never advertise a next_offset above 16777216: when more content would require such a cursor, fail with invalid_input and guidance to use the artifact download link instead. No Range assumption is required. Canceled requests abort promptly.

`get_workflow_nodes` and `get_workflow_artifacts` gain optional archive_uid while retaining required name for compatibility. Both use a shared authorized workflow-data lookup. Nodes gain input_parameters, output_parameters, output_result and exit_code. Values use the existing parameter string representation, at most 128 parameters and 4096 bytes per value; result at most 16384 bytes. Existing truncated metadata must truthfully reflect any clipping.

`get_workflow_logs` retains workflow_name, namespace, container (default main), pod_name, search, max_lines and existing output fields. It adds source auto/live/archive (default auto), node_id, archive_uid and max_bytes default 1048576 (1024–4194304). Results add source, truncated and note. Live reads and archive reads are bounded by max_bytes; counts refer to the collected bounded content, and the note makes clear that a truncated prefix is not the latest global tail.

| Condition | Behavior |
| --- | --- |
| source live | Existing live log route; archive_uid or node_id is rejected because these select archive nodes. |
| source auto without archive_uid/node_id | Read live first. Nonempty logs return live. Empty success or HTTP 404 permits archive fallback. Other errors, including authentication, cancellation and temporary failures, remain errors. |
| source archive, or auto with archive_uid/node_id | Read declared output artifacts named exactly `${container}-logs`; never substitute another container. node_id selects exactly that node (unknown ID fails). Otherwise sort nodes by ID, inspect at most 20 matching nodes and flag truncation when more exist. Use one aggregate max_bytes budget. |
| pod_name with archive fallback | Reject with guidance to replace pod_name with node_id, avoiding guesses across Argo pod-name versions. pod_name plus node_id is always rejected. |
| No matching archive log artifact | Successful empty result with source archive and explicit absence note. Retrieval errors for declared artifacts remain errors. |

For live logs max_bytes caps HTTP body bytes including SSE/JSON framing; retain only complete frames in a truncated prefix. A frame larger than the whole budget with no complete entries fails with guidance to increase the budget, never an empty-success fallback. For archive logs max_bytes caps aggregate artifact bytes. Rendered logs are additionally capped at max_bytes on a UTF-8 boundary and marked truncated. Search and max_lines run after bounded collection; preserve existing case-insensitive search across text and pod names, and tail behavior within the collected content. An auto fallback records why it occurred. Workflow archive retention and log artifact retention are distinct: an archived workflow need not have retained logs.

## Optional Kubernetes diagnostics

Kubernetes-specific service errors are `kubernetes_configuration_error` (permanent, configure KUBERNETES_API_URL and credentials), `kubernetes_access_denied` (permanent for 401/403, check Kubernetes token and pods/events RBAC), `kubernetes_not_found` (permanent for 404, rediscover the current pod), `kubernetes_api_error` (temporary for network timeout/429/5xx, check connectivity and retry), and `kubernetes_response_error` (permanent for other 4xx, malformed/oversize/identity-invalid replies, check inputs/server compatibility). Each has a Kubernetes-specific safe message and remedy code, and never exposes a response body or credentials. Local argument errors use existing invalid_input; namespace denials retain namespace_denied. Main parent cancellation remains an error. Event errors of every kind become safe per-pod events_error, except parent cancellation, which aborts the tool.

`KUBERNETES_API_URL`, `KUBERNETES_TOKEN`, `KUBERNETES_CA_PEM` configure a dedicated client; no kubeconfig, shell calls, ambient credentials or implicit in-cluster discovery. URL must be HTTPS with no credentials, query or fragment; HTTP is accepted only for literal loopback addresses in local tests/development. The entire diagnostics call has a 10-second child deadline, and each HTTP request also has a 10-second timeout. Caller cancellation aborts the call. An expired diagnostics deadline aborts the call as a temporary Kubernetes API error; it does not keep issuing event requests. CA PEM is optional; system roots are the default, invalid supplied PEM fails startup. Unconfigured URL means the tool returns a configuration error without Argo or Kubernetes calls. Partial credential/CA configuration without URL fails startup.

Pod lists use `/api/v1/namespaces/{namespace}/pods`, labelSelector `workflows.argoproj.io/workflow=<name>`, limit and continue. One upstream page per call, with matching-owner items only; empty filtered pages may still have continuation. More than the requested count is rejected. pod_name uses a direct pod GET then checks workflow label, namespace and owner UID; continue is invalid with pod_name. A foreign-owner pod is never returned. The caller must have pods and events read permissions. No permissions are inferred from Argo credentials.

For each returned pod, read `/api/v1/namespaces/{namespace}/events` with fieldSelector involvedObject.uid and limit 20; verify involvedObject UID and namespace before returning events. Event continuation becomes events_truncated; event permission failures become an explicit per-pod events_error while preserving useful pod state. Main pod/Argo errors fail the tool. Limit all HTTP response bodies to 4 MiB. Cap conditions and container statuses at 50 each, messages at 4096 bytes and names/identifiers at 256 bytes with visible truncated flags. The entire serialized tool result is capped at 1 MiB: exceedance fails with guidance to lower limit or select pod_name, rather than silently skipping pods in a page. Do not return pod environment variables, secret references or full specs. Refuse cross-origin redirects.

## Deadlines, context and confidentiality

Wait owns a deadline covering the initial read and all polls; retain the last successful detail. Own deadline expiry returns timed_out=true when a detail exists; expiry before a successful read is an upstream timeout error. Parent cancellation is always an error. All other errors stop immediately. Poll interval may exceed the duration; no overlapping requests or background polling after return.

Context reads use `/api/v1/version` under a 3-second child deadline. An unconfigured Argo reports unconfigured, a failed call reports unavailable with no raw upstream text, and successful reads expose the version. Other local context is still returned. The tool never exposes token/password/CA/URL values. Audit output must redact all artifact/log/spec contents and parameter values and retain only safe identifiers/counts/outcomes.

## Result schemas

All fields below are required unless marked optional; list/map fields use empty collections rather than null. Additive fields on existing results may be optional where needed for compatibility.

| Result | Fields |
| --- | --- |
| ArtifactContentResult | namespace, name, node_id, artifact_name, direction, text, offset_bytes, returned_bytes, has_more, source=`argo`; optional next_offset only when has_more, optional note. archive_uid is optional echo. |
| ResourceSpecResult | kind, name, section, spec_json, source=`argo`; namespace omitted for cluster scope; optional template_name. |
| WorkflowPodDiagnosticsResult | namespace, name, pods, count, has_more, truncated, source=`kubernetes`; optional continue only when has_more. Pod entries have name, uid, phase, node_name, conditions, init_containers, containers, events, events_truncated, truncated; optional events_error. Conditions: type,status,reason,message. Containers: name,restart_count,ready,state,last_state. State: status waiting/running/terminated/unknown, reason,message; optional exit_code,started_at,finished_at. Events: type,reason,message,count,first_timestamp,last_timestamp. |
| WaitWorkflowResult | workflow of existing WorkflowDetailResult type, completed, timed_out, source=`argo`. |
| ServerContextResult | build_version, mcp_version, transport, default_namespace, allowed_namespaces, denied_namespaces, allow_mutations, allow_destructive, require_confirmation, argo_configured, kubernetes_configured, argo_status unconfigured/available/unavailable, note; optional argo_version (the upstream version field only). Configured means URL is present and startup configuration validated. |

Artifact source is argo because both live and archived artifact endpoints belong to Argo; log source is live/archive because it identifies retention behavior. The design and runtime context share `internal/version.MCPVersion`, without a second handwritten version constant or importing the design DSL into runtime bootstrap. Build version is injected by server bootstrap. Declared pod fields absent upstream use empty strings, zero counts or unknown state as appropriate.

## Release identity and compatibility

Design MCP version is 0.3.0. Release builds use the same version for the CLI linker field. A reusable `cmd/verify-release` takes an explicit binary path and expected version, executes `--version` and an official SDK stdio initialize, verifies name and version, and fails on mismatch. Child environment is sanitized, audit disabled, execution bounded, and processes reaped. The release workflow invokes this against a candidate built with release flags before publishing. The same binary verifier applies to the downloaded checksum-verified release. Separate SDK HTTP verification targets the installed server at its configured local /rpc endpoint and checks the initialize identity and tool catalog after restarting the launcher.

Existing callers remain valid except that explicit impossible source/filter combinations now have clear validation. Required legacy string fields remain required strings. New result fields are additive. Mutation guards and namespace authorization do not change. A forgotten design version bump is a release-blocking failure. Runtime environment must not affect generation.

## Proof obligations

The contract requires generated schema and behavior parity on stdio, HTTP and stateless HTTP; namespace denial before I/O; archived identity checks; traversal/redirect/credential isolation; bounded reads and UTF-8 pagination; honest empty/error/truncation logs; exact container selection; spec preservation and size rejection; canceled waiting; Kubernetes ownership/event isolation and unconfigured behavior; output redaction; existing mutation safety; CLI/MCP version mismatch rejection. Real Argo checks must exercise archived frontend logs and text artifact contents as well as live reads. Optional Kubernetes tests use HTTP fixtures unless a connection is provided; that limitation must remain explicit.
