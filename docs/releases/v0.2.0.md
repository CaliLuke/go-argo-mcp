# go-argo-mcp v0.2.0

This release expands the server from 13 to 25 tools and adds local and stateless transport options while preserving read-only defaults.

## Highlights

- Twelve new tools cover workflow nodes and live events, archived workflow listing and details, artifact metadata and safe Argo download links, workflow and template linting, template submission, workflow suspend, resume, and resubmit operations, and CronWorkflow triggering.
- Collection, node, artifact, event, and archive results use bounded pagination or collection windows, with explicit continuation and truncation signals.
- The server now supports `stdio`, stateful Streamable HTTP, and stateless Streamable HTTP transports.
- Audit records redact credentials, lint manifests, workflow logs, confirmation tokens, and submitted parameter values while retaining bounded operational summaries.

## Upgrade notes

- `retry_workflow` and `terminate_workflow` now require both `MCP_ALLOW_MUTATIONS=true` and `MCP_ALLOW_DESTRUCTIVE=true`.
- `retry_workflow` defaults to preview mode. Dispatch requires an explicit `dry_run: false`; with the default confirmation policy, first create a preview and then provide its scoped, one-time confirmation token with the matching request.
- HTTP listens on loopback by default. A non-loopback listener requires `ARGO_MCP_AUTH_TOKEN` or an explicit `ARGO_MCP_ALLOW_UNAUTHENTICATED=true` acknowledgement for authentication handled by a trusted proxy or service mesh. Wildcard listeners also require `ARGO_MCP_ALLOWED_HOSTS`.

## Diagnostics and archives

Archive tools expose bounded archived workflow summaries and details. Artifact discovery returns metadata and safe links through the configured Argo server; it does not download artifact bytes. `get_workflow_logs` reads live workflow pods only and does not fall back to archived logs.
