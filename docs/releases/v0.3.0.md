# v0.3.0

This release adds five read-only diagnostic tools and recovers retained logs when workflow pods are gone.

- `read_workflow_artifact` reads declared UTF-8 text artifacts in bounded, paginated chunks.
- `get_resource_spec` exposes workflow, template and CronWorkflow arguments, templates and full specifications.
- `get_workflow_pod_diagnostics` reports owned pod states, restarts, termination reasons and events through optional Kubernetes API access.
- `wait_workflow` waits for completion within a bounded interval and returns the latest status.
- `get_server_context` reports versions, configured backends and local policy without credentials.

Workflow logs now support `auto`, `live` and `archive` sources, exact node selection and byte limits. Automatic fallback uses retained artifacts when live logs are empty or unavailable with HTTP 404. It preserves the requested container: absent `wait` logs never become `main` logs. Deleted workflows require an explicit archive UID. Node inspection also returns bounded input/output parameters, script results and exit codes; node and artifact reads support archived workflows.

MCP initialization now advertises the release version. A new pre-publication check verifies that the binary's CLI and MCP versions agree. The tool catalog grows from 25 to 30 across stdio, HTTP and stateless HTTP.

The server remains read-only by default. Existing Argo configuration continues to work. Pod diagnostics requires separate `KUBERNETES_API_URL` configuration, optional `KUBERNETES_TOKEN`, and optional `KUBERNETES_CA_PEM`; it does not discover kubeconfig credentials.

Upgrade on macOS with:

```sh
brew update
brew upgrade --cask CaliLuke/tap/go-argo-mcp
```

Restart the MCP server after upgrading. See the README for tool limits, archive selectors and Kubernetes setup.
